# Plan: nmap host-discovery on the connected LAN (Generator Epic — Story 2)

**Branch**: `feat/v2-nmap-lan-scan` (per-slice branches below)
**Status**: Proposed — blocked on Story 1.5 (`plans/apt-install.md`); start after `apt install nmap` ships
**Parent epic**: `plans/network-generator-epic.md` → Story 2 ("A reachable single-layer LAN you can scan")

## Goal

A player who is **online on a home network** runs `nmap <subnet>` and sees a
deterministic list of generated hosts on their LAN — IP, hostname, kind
(`machine`/`router`), with `.1` as the gateway. Same identity + ESSID → identical
LAN, every reload. First time topology + addressing become real and observable.

## Context the plan rests on (verified)

- **PRNG already exists** in v2 (`core/generation/prng.ts`) — no port needed.
- **Connectivity model exists**: `core/network/interfaces.ts` exports `isOnline(state)`;
  `env.network.isOnline()` is the gate. `env.network.interfaces()` yields the NICs.
- **You join a LAN already**: `core/network/homeNetwork.ts → assignHomeNetwork(pubkey, essid)`
  returns `{ localIp: '192.168.X.Y', hostname }`. The subnet you scan is `192.168.X.0/24`,
  gateway `.1`. This is the natural, already-wired target.
- **Reachability**: `nmap` is acquired via `apt install nmap` (Story 1.5, `plans/apt-install.md`),
  NOT preinstalled. `nmap`'s availability rule is `{ kind:'installed-package', packageName:'nmap' }`;
  the binary appears in `/usr/bin` only after install. (Earlier "preinstall" idea dropped per owner.)
- **Subnet variety**: the shipped `assignHomeNetwork` is hard-coded to `192.168.X.Y`. Story 2
  widens it to the full RFC 1918 draw (`10.x` / `172.16–31.x` / `192.168.x`) like legacy
  `generatePrivateSubnet`, then the scan renders whatever subnet the player landed on. Update the
  existing golden test (no live players → free to reshape).
- **Command shape**: `Command` with `execute(env, args, flags) => CommandResult`; registered in
  `core/commands/registry.ts` `builtins[]`; auto double-wrapped (binary check outer, library
  check inner). Streaming reference: `nmcli.ts` / `airdump.ts` (async generator + `env.sleep`,
  abort-aware via `env.signal`).

## Decisions baked in (CONFIRM before coding)

1. **Reachability — via `apt install nmap`, NOT preinstalled.** `nmap`'s availability is
   `{ kind:'installed-package', packageName:'nmap' }`; the player installs it (Story 1.5) before
   it runs. _Rationale_: owner decision — `apt install` is the real mechanism; preinstalling was a
   hack. This plan is therefore blocked on `plans/apt-install.md`.

2. **Flag set — `nmap <subnet>`, host-discovery output only; NO `-sn` flag.** Legacy `nmap`
   (`src/commands/nmap.ts`) supports `-sV`/`-sU`/`--tree` and **never had `-sn`** — range scan
   was the default invocation `nmap <subnet>`. Ports/CVEs are explicitly OUT of this epic, so
   the range scan naturally renders host-discovery rows only; when the ports epic lands, the
   same `nmap <subnet>` grows port columns. This honours
   `feedback_v2_match_legacy_command_interface` (don't invent flags). _Deviation note_: the epic
   text says "e.g. `-sn`" — that was an offhand reference; we are deliberately NOT introducing it.
   `--tree` is deferred to Story 4 (multi-layer), where a tree is meaningful.

3. **Determinism seed.** LAN hosts are generated by a new pure
   `generateHomeLan(seedPubkeyHex, essid)` that re-derives the player's `192.168.X.Y` assignment
   (reusing `assignHomeNetwork`), places the gateway at `.1`, and seeds sibling hosts from the
   same `home-…` namespace. True cross-player LAN sharing is deferred with the server-authoritative
   join (documented in `homeNetwork.ts`); for now the LAN is deterministic per identity+ESSID.

4. **Streaming, abort-aware.** Reuse the async-generator + `env.sleep` pattern (nmcli/airdump
   family) for a live-scan feel; cancels on Ctrl-C via `env.signal`. Pacing is light and the only
   delay (generation itself is pure/instant). _Alternative_: sync render if we'd rather avoid any
   cosmetic delay.

## Acceptance Criteria

- [ ] While **offline**, `nmap 192.168.0.0/24` (or any subnet) errors clearly and does not list hosts.
- [ ] While **online** on a home network, `nmap <currentLanSubnet>` lists the gateway at `.1`
      (kind `router`) and the player's own host.
- [ ] The scan lists additional generated hosts, each with a unique last octet (never `.1`, never
      the player's octet), an IP, a hostname, and a kind (`machine`/`router`).
- [ ] Same identity + ESSID ⇒ byte-identical host list across reloads (determinism).
- [ ] `nmap` becomes runnable only **after `apt install nmap`** (availability `installed-package:nmap`);
      before install it errors with the `command not found` + install hint. `help`/`man` list it under `network`.

### Slice 1: `nmap <subnet>` shows the gateway + you (walking skeleton)

**Value**: Player, online on a LAN, runs recon and sees they're on a real, addressed network
(gateway `.1` + self) — proving the topology+addressing+command path end-to-end.
**Path**: `nmap` command (availability `installed-package:nmap`) → reads `env.network.isOnline()`
+ the connected interface's IPv4 to derive the current `/24` subnet → pure `generateHomeLan`
returns at minimum the gateway (`.1`, router) + the player's host → async-streamed `TerminalLine`s
→ terminal. Offline (or nmap not installed) → error. Skipped for now: other hosts (Slice 2), ports,
`--tree`, scanning arbitrary/foreign subnets.
**Required implementation skills**: `tdd`, `testing`, `mutation-testing`, `refactoring`.
**Acceptance criteria**: offline → error + no hosts; online → gateway `.1` (router) and own host
rendered; command registered + gated by `installed-package:nmap` (runs only post-`apt install nmap`)
+ categorised `network`. **Confirm before code.**
**RED**: unit test on `generateHomeLan` (gateway at `.1`, includes self, deterministic) +
command test asserting offline-error vs online gateway/self rendering. Mutator watch:
off-by-one on the `.1` gateway octet, boundary on the online predicate, swapped error/normal exit.
**GREEN**: minimal `generateHomeLan` (gateway + self) + `nmap` command + registry wiring
(availability `installed-package:nmap`) + widen `assignHomeNetwork` to full RFC 1918.
**MUTATE / KILL MUTANTS / REFACTOR**: per skills.
**Done when**: all criteria met, mutation report reviewed, human approves commit.

### Slice 2: deterministic LAN population (the other hosts)

**Value**: Player sees a populated LAN — multiple generated hosts to target later — and the same
network every time they reconnect.
**Path**: extend `generateHomeLan` to draw a seeded host count and emit N sibling machines with
unique last octets (excluding `.1` and the player's octet), seeded hostnames, and `machine`/`router`
kinds → `nmap` renders the full sorted list. Skipped: multi-layer depth (Story 4), ports.
**Required implementation skills**: `tdd`, `testing`, `mutation-testing`, `refactoring`.
**Acceptance criteria**: N hosts with unique octets, no collisions with `.1`/self; stable hostnames;
identical list across reloads for same identity+ESSID. **Confirm before code.**

The `<subnet>` arg stays **required-but-decorative** through Slice 2 (value unused, banner prints
`x.y.z.0/24`); **Slice 3** makes it meaningful via the legacy range syntax.

### Slice 3: legacy range-scan syntax (`x.y.z.A-B`)

**Value**: the player targets a host range like legacy nmap — `nmap 192.168.1.20-80` scans only that
slice of the LAN — instead of the decorative `<subnet>` arg.
**Path**: parse + validate the argument as `x.y.z.A-B` (`feedback_v2_match_legacy_command_interface`)
— **not** CIDR `x.y.z.0/24` — (A ≤ B, octets ≤ 254; malformed → usage error), **filter** the
`generateHomeLan` hosts to those whose last octet ∈ [A,B], and echo the range in the banner + manual
examples. Foreign-subnet scanning (typed `x.y.z` ≠ the current LAN) stays deferred (Story 4-adjacent):
a non-matching network errors / is out-of-scope.
**Required implementation skills**: `tdd`, `testing`, `mutation-testing`, `refactoring`.
**Acceptance criteria**: valid `A-B` parses + filters; out-of-range hosts excluded; malformed → usage
error; banner/manual show the range. **Confirm before code.**
**Why its own slice**: range filtering is only observable once the LAN is populated (Slice 2), so it
rides on top of it; no live players ⇒ reshaping the arg later is free.
**RED**: determinism/uniqueness tests (no duplicate octets, never `.1`/self, count within range,
golden host list for a fixed seed). Mutator watch: octet-uniqueness loop, count bounds, exclusion
filters.
**GREEN**: seeded population logic.
**MUTATE / KILL MUTANTS / REFACTOR**: per skills.
**Done when**: all criteria met, mutation report reviewed, human approves commit.

## Deliberately out of scope: scan logging

nmap leaving a trace in the target's `/var/log/kern.log` (legacy parity, and the primary
cross-player discovery mechanism) is **not** part of this plan. The hosts this plan scans are
pure-generated placeholders with no `machine_id`, no server-side patch stream, and no remote write
seam — there is nowhere to persist a trace and no second player who could read it. Logging +
the `AMBIENT_LOG_FILES` L1/L2 bypass are specced in `plans/scan-logging-cross-player.md`, hard-blocked
until scanned hosts become real, server-persisted machines. Deferred, not forgotten.
